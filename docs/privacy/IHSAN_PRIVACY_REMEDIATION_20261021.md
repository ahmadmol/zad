1. نُقح تقرير الملف الشخصي في مكانه كي تبقى مراجع الوثائق صالحة. لا تُستبدل الأدلة التاريخية بنتائج اختبار اصطناعية؛ مواضع الهوية تحمل إشارة تنقيح صريحة.
2. حُفظ أصل التقرير، وأصول خمسة تقارير من Batch01–04/Sprint01 قبل تنقيح مسار حساب Windows، داخل `.artifacts/github-safe-push-20261021/original-documents/`. الأصول محلية ومُستبعدة؛ لم تُحذف قواعد البيانات أو الصور أو الملفات المحلية.
3. أُنشئ [مثال اصطناعي](fixtures/synthetic-profile.json) من الصفر مع توثيق مصدره. يستخدم اسم اختبار ورمز هاتف **غير قابل للاتصال**، ولا يُشتق من البيانات الفعلية. ليس fixture لاختبار صحة رقم هاتف، ولا يدخل أصول التطبيق.
4. حُدّث `.gitignore` لقواعد الهاتف وsidecars وarchives المسمّاة وruntime/UI dumps وlogs ومفاتيح التوقيع والمخرجات الخام. بقيت مصادر Kotlin/Compose والموارد وGradle Wrapper ومخططات Room9/10/11 والترحيلات والاختبارات والأصول المعتمدة خارج قائمة الإزالة.
5. جُهزت [قائمة مسارات محددة](PRIVATE_ARTIFACT_PATHS.txt) بـ**1,425 ملفًا متتبعًا**: 329 UI/XML، و508 logs/raw evidence، و576 لقطة/وسيطًا، و10 قواعد/sidecars، وأرشيف واحد، وملف Markdown محلي داخل `.artifacts`. هذه قائمة عزل احترازي للمخرجات، **وليست ادعاء وجود بيانات شخصية في كل ملف**. التقارير المنسقة تبقى قابلة للتتبع بعد تنقيحها.
6. تحققت مطابقة كل مسار مُعد للإزالة لقواعد الاستبعاد، وسُجلت بصمات الملفات المحلية قبل إزالة التتبع. **قائمة الإزالة جاهزة، لكن index لم يُعدل ولم تُنفذ `git rm --cached` بعد.**

ملفات الجرد التفصيلي ونتائج الفحص وأسماء المسارات فقط داخل `.artifacts/github-safe-push-20261021/`. لا تحتوي النتائج قيم الهوية. النسخ الأصلية المنفصلة ما زالت حساسة ويجب ألا تُشارك أو تُضم إلى أرشيف GitHub.

## إزالة التتبع في الحالة الحالية

المسارات الدقيقة موجودة أيضًا في ملف NUL محلي لتجنب تفسير wildcard. عند تنفيذ المعالجة الحالية محليًا يمكن استعمال:

```powershell
git --literal-pathspecs rm --cached --pathspec-from-file=.artifacts/github-safe-push-20261021/untrack-paths.nul --pathspec-file-nul
```

هذا الأمر **لم ينفذ**. لا يحذف ملفات العمل ولا ينظف التاريخ. يجب بعده التحقق من بقاء كل ملف وبصمته، ومراجعة staged deletions، والتأكد من بقاء المصدر ومخططات Room والترحيلات وWrapper. لا يُستخدم `git add .` أو حذف مجلدات أو clean/reset. لا يُرفع حتى Commit الإزالة قبل حسم معالجة التاريخ مع المالك.

## خطة التاريخ المنشور — تحتاج موافقة منفصلة

1. إيقاف الكتابة مؤقتًا والتنسيق مع المساهمين؛ حفظ عمل Batch01–05 والنسخ الأصلية في مساحة محلية خاصة. حصر جميع refs والفروع والتاغات وPR refs والفروع المتفرعة قبل اعتماد قائمة المعالجة النهائية. حُصر حاليًا فرعان معلنان فقط؛ الفحص ليس ضمانًا لغياب clones أو forks أو cache.
2. بعد الموافقة، استخدام نسخة معزولة جديدة و`git-filter-repo` الداعم لـ`--sensitive-data-removal` (2.47 أو أحدث). حذف **مسارات exports/archives/captures** من التاريخ، مع تتبع أسمائها السابقة. تنقيح تقرير QA ونسخ `ProfileScreen.kt` التاريخية بـ`--replace-text`؛ لا حذف ملف Kotlin أو الأصول المعتمدة. ملف أنماط الاستبدال يُجهز محليًا من الأصل المحمي دون طباعة قيمه أو تتبعه.
3. إعادة الفحص لكل refs والتأكد من بناء المصدر واتساق المخططات، وتوثيق First Changed Commits وchanged refs. المحافظة على التعديلات غير المنشورة باستيراد فرق المصدر المنقح فقط؛ لا merge لتاريخ قديم ملوث.
4. بعد موافقة صريحة على **refs محددة**، تحديث الفروع/التاغات المتأثرة بالطريقة المعتمدة لإعادة كتابة البعيد. لا `--mirror` أعمى أو حذف فروع أو تعديل branch protection/خصوصية المستودع تلقائيًا. هذا يتطلب صلاحية force push ولم تُمنح بعد.
5. التنسيق مع GitHub Support لإزالة cached views وPR references عند الحاجة؛ لا تُرسل رسالة أو تذكرة دون تفويض. إخطار المساهمين بإعادة الاستنساخ أو تنظيف نسخهم، وعدم دمج التاريخ القديم. لا يمكن ضمان إزالة نسخ سبق أن استنسخها طرف آخر.

الأثر: تتغير SHA للـCommits المتأثرة وما بعدها، وقد تتأثر توقيعات Commits/tags وروابط المراجعات وPRs وCI. كل فرع أو clone يستند إلى التاريخ القديم يمكنه إعادة البيانات بالخطأ. يجب فحص main وكل refs مجددًا؛ لا نفترض حاجته لإعادة كتابة لمجرد وجود مسار برمجي مشترك. [مرجع GitHub الرسمي](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).

## الأسرار وحدود الفحص

لم تتوفر gitleaks/trufflehog محليًا؛ استُعمل ماسح أنماط محلي تُحجب فيه القيم. فُحصت 2,356 نسخة نصية منشورة لمفاتيح خاصة وGitHub/AWS/Slack tokens وJWT وURLs ذات credentials وcredential assignments. لم تثبت أسرار مشروع تتطلب إبطالًا أو تدويرًا. ظهرت مرشحات Google API keys داخل أربع صفحات Google/YouTube محفوظة؛ مواضعها مواد صفحات عامة ولا دليل في الفحص أنها اعتماديات خاصة للتطبيق، وتدخل المخرجات المستبعدة. هذا ليس ضمان غياب أسرار خارج النطاق: لم تُفكك نسختا APK الكبيرتان، ولم تُفحص بكسلات الصور أو نسخ GitHub الخارجية.

رقم الهاتف والاسم ليسا بيانات اعتماد يمكن تدويرها لحل هذا التعرض. إذا اكتُشف token أو مفتاح خاص فعلي لاحقًا، يُبطل/يدور أولًا قبل تنظيف التاريخ، دون اختبار صلاحياته أو عرضه.
